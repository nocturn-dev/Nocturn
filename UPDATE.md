# UPDATE.md — журнал изменений Nocturn

> Правила ведения (обязательно для новых сессий):
>
> 1. **Новые записи добавляются СВЕРХУ** (свежее — выше).
> 2. Формат записи: `## ГГГГ-ММ-ДД · [теги] Название`, под ним 1–4 буллета
>    деталей и **хэш коммита** (коммит обязателен: verify зелёный → коммит → запись).
> 3. Теги (можно несколько через ` · `):
>    - `new-feature` — новая функция
>    - `hot-fix` — быстрый точечный фикс
>    - `global-fix` — фикс, затрагивающий систему/много мест
>    - `rebuild` — переписан механизм/компонент
>    - `update-backend` — тронут Rust (`src-tauri/`)
>    - `update-frontend` — тронут фронтенд (`src/`)
>    - `refactor` — переструктурирование без нового поведения
>    - `experiment` — экспериментальная функция (помечена в UI)
>    - `infra` — инфраструктура/инструменты/правила
>    - `docs` — только документация
> 4. Один логический изменение = одна запись. Большие пачки — одна запись со
>    списком буллетов, не простыня из двадцати записей.
> 5. Старые записи не удалять и не редактировать задним числом.
> 6. Если фикс — рядом одним предложением «причина → что сделано».

## 2026-10-01 · [hot-fix · update-frontend] Окно YouTube-плеера: поверх контента, центр по зоне чата, поле ссылки в зоне видео
- **Причина (скрин владельца: окно «уходило за сайдбар» и под контент чата)**: inline `style.zIndex: var(--halo-z-modal)` в WebView2 не применился — все модалки ставят z классом `z-[var(--halo-z-modal)]`, слой переведён на тот же паттерн. Окно теперь над приветствием/композером, клики в него больше не проваливаются в чат.
- **Центр по зоне чата, не окна**: fixed-инсеты равны ширине сайдбара с его стороны (свёрнутый = 0) — окно больше не «смотрит влево» и физически не заезжает под сайдбар. Фон сплошной deep вместо полупрозрачного — контент не просвечивает.
- **Удобство ввода**: без трека зона видео — большое текстовое поле (автофокус, Enter — включить, ошибка ссылки инлайн); нижняя строка появляется только с треком и служит для очереди. Подсказка бинда — постоянный футер.
- Коммит: `294612a`.

## 2026-10-01 · [hot-fix · update-frontend] Шиммер-текст заработал: бесшовный цикл + динамический цвет, починен гейт минибара
- **Причина (фидбек владельца «переливание не работает»)**: две ошибки. Селектор минибара `html.media-text-shimmer` никогда не совпадал — класс вешается на корень MediaBar, а не на `<html>` (тумблер «Интеграций» был мёртв). И геометрия градиента: при background-size 300% полоса 42–58% не попадала в видимое окно при позициях 0% и 100% — текст мерцал лишь секунды в середине 12-секундного цикла.

Смена строки лирики перезапускает проход (кареоке-поведение), плитка артиста крутится непрерывно.

## 2026-10-01 · [fix · update-backend] Spotify Desktop без SMTC: оконный fallback (заголовок окна + WM_APPCOMMAND)
- **Причина (диагностика зондом на машине владельца)**: клиент Spotify не регистрирует SMTC-сессию вовсе (известное поведение Store/модифицированных сборок), при этом заголовок главного окна несёт «Artist — Track — Album» во время воспроизведения и становится просто «Spotify» на паузе.
- **Фикс**: Desktop-режим при молчащем SMTC переключается на оконный путь — раз в секунду читается заголовок окна spotify.exe (процессы через Toolhelp, окна через EnumWindows), парсится «Artist — Track»; пауза = заголовок «Spotify» → липкий трек со статусом ⏸ (не пропадает); позиция тикает локально от старта трека (ОС её не отдаёт); управление — WM_APPCOMMAND (play-pause/next/prev, проверено зондом `--toggle`: клиент реально тогглится). Обложки в оконном пути нет.
- Ограничение браузерного режима задокументировано честно: SMTC не отдаёт URL вкладки, поэтому фильтр «только spotify.com» невозможен без браузерного расширения — режим ловит любые медиа-вкладки.
- Коммит: `39062f3`.
