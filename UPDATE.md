# UPDATE.md — журнал изменений Nocturn

> Правила ведения (обязательно для новых сессий):
>
> 1. **Новые записи добавляются СВЕРХУ** (свежее — выше).
> 2. Формат записи: `## ГГГГ-ММ-ДД · [теги] Название`, под ним 1–4 буллета
>    деталей и **хэш коммита** (коммит обязателен: verify зелёный → коммит → запись).
> 3. Теги (можно несколько через ` · `):
>    - `new-feature` — новая функция
>    - `hot-fix` — быстрый точечный фикс
>    - `global-fix` — фикс, затрагивающий систему/много мест
>    - `rebuild` — переписан механизм/компонент
>    - `update-backend` — тронут Rust (`src-tauri/`)
>    - `update-frontend` — тронут фронтенд (`src/`)
>    - `refactor` — переструктурирование без нового поведения
>    - `experiment` — экспериментальная функция (помечена в UI)
>    - `infra` — инфраструктура/инструменты/правила
>    - `docs` — только документация
> 4. Один логический изменение = одна запись. Большие пачки — одна запись со
>    списком буллетов, не простыня из двадцати записей.
> 5. Старые записи не удалять и не редактировать задним числом.
> 6. Если фикс — рядом одним предложением «причина → что сделано».

## 2026-09-30 · [hot-fix · update-frontend · update-backend] Drag&drop файлов реально заработал: выключен нативный drop-target Tauri на главном окне
- **Причина**: HTML5 drag-drop из прошлого фикса был мёртв с рождения — у окна по умолчанию `dragDropEnabled: true`, и wry ставит на WebView свой OLE drop-target (`DragDropController`), глотая системные перетаскивания: до JS-слушателей события не доходили вовсе («вообще не реагирует», дроп невозможен в любом сценарии). Документировано в tauri-utils: «Disabling it is required to use HTML5 drag and drop on the frontend on Windows».
- **Фикс**: `"dragDropEnabled": false` на главном окне (потребителей нативных tauri drag-событий в коде нет; drag-region заголовка не задействован). QuickEntry не тронут — там случайный дроп с включённым нативным обработчиком не уводит окно в навигацию. Страховка от зависшего оверлея: сброс drag-стейта на blur/скрытии окна (Alt+Tab посреди перетаскивания может не прислать dragleave). Рабочий сценарий после фикса: тянешь файл → таскбар (ОС) → клик по Nocturn → появляется оверлей → отпускаешь — файл вложен. **Требуется перезапуск `tauri dev`**: конфиг окна запекается при сборке.
- Коммит `1535e22`.

## 2026-09-30 · [hot-fix · update-frontend] Ambient-сцены независимы от темы: убраны затемнение и «коричневение» (туман/снег/неон-сити/звёзды)

Корень — тройной: (1) сцены заливали весь экран НЕПРОЗРАЧНЫМ «небом» из палитры стиля (deep/bg — тёплый коричневый клод-палитры), это было зафиксировано в шапке модуля как решение; (2) в «Поверх интерфейса» слой с opacity 0.7 лежал НАД UI плюс `.ambient-layer::after` добавлял второй тёмный градиент; (3) в «За интерфейсом» панели 86%-прозрачности просвечивали тем же коричневым небом. `sceneTint()` к тому же брал hue тёплых поверхностей с форсированной насыщенностью — дымки/фонари/туманы были коричневыми.
- **Фикс**: у каждой canvas-сцены своя зашитая ночная палитра (туман — холодный серо-голубой, снег — синяя ночь с янтарными фонарями, неон-сити — синий вечер с cyan-неоном и тёплыми окнами, звёзды — космос с синими/фиолетовыми туманностями); небо рисуется ПОЛУПРОЗРАЧНЫМ (0.45–0.55) — UI просвечивает и в режиме «Поверх»; тёмный `::after`-градиент удалён; в «За интерфейсом» под слой CSS кладёт тёмную подложку `#05070c` (иначе сквозь полупрозрачное небо в щелях светил бы белый фон окна WebView). Удалён MutationObserver/перезапекание по теме — сценам тема больше не нужна (минус observer + getComputedStyle на каждую мутацию корня).
- **Настройки не тронуты**: выбор сцены, интенсивность, «За интерфейсом»/«Поверх интерфейса» работают как раньше; сцена gradient (конструктор с цветами пользователя) и видео не менялись.

## 2026-09-30 · [hot-fix · update-backend] Криптомодуль: точечные фиксы по внешнему ревью (гонки, poison, Argon2-параметры, zeroize)
- **Причина**: независимое ревью crypto.rs (Claude) — 10 из 12 замечаний подтвердились проверкой по коду и метаданным крейтов → точечный батч.
- **vault_guard**: проверка простоя и стирание ключа — под одной блокировкой (раньше `if vault_idle_expired() { clear_key(); }` в has_key/encrypt/decrypt оставлял окно, где clear_key стирал только что установленный другим потоком ключ); `unwrap_or_else(|p| p.into_inner())` в touch_vault/set_key/clear_key/has_key — стирание при poison больше не no-op (ключ оставался в памяти при has_key() = false).
- **Dual-таймер авто-запирания**: Instant на Linux/macOS не идёт во время сна — закрытый на ночь ноутбук продлевал 15-минутное окно на всё время сна. Добавлен страхующий SystemTime-таймер (истечение по ЛЮБОМУ из двух; NTP-скачок назад не считается истечением). Порядок блокировок глобально зафиксирован VAULT_KEY→LAST_USE→LAST_USE_WALL. Свипер lib.rs переведён на vault_sweep() — тот же гейт без гонки.
- **Argon2-параметры явными**: `Params::new(19*1024, 2, 1, Some(32))` вместо Params::default() — дефолт был свойством версии крейта (в 0.4: m=4 MiB, t=3); числа совпадают с default() 0.5, ключи существующих пользователей не меняются. Подъём параметров = отдельная миграция по kdf-метке.
- **Zeroize-гигиена**: фича `zeroize` у aes-gcm (развёрнутый ключ AES теперь затирается при drop — ранее не входила в default features); буферы KDF в Zeroizing с момента выделения (ранний `?` в argon2-ветке дропал незатёртый производный ключ); make_check сведён к encrypt_with (дубликат механизма расходился бы при правках); тест авто-запирания с инъекцией окна/времени (без sleep); опечатка в тесте.
- **Не делалось (вне «точечного»)**: AAD-привязка имени поля (формат enc:v2 + миграция), Result-типизация decrypt вместо Option, mlock. Зафиксировано как возможные следующие шаги.
- Замечено ревью и отклонено: совет про `rand::rng()` (проект на rand 0.8, не 0.9) и «зафиксируйте rust-version» (уже зафиксирован 1.88 и покрывает используемые is_multiple_of/as_chunks).
- `verify all` зелёный; cargo test 131 (+тест авто-запирания) + e2e + clippy `-D warnings`.
