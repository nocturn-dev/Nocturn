### А5-1. [ВЫСОКИЙ] SSRF-тумблер «Разрешить приватные сети» в Browser Use — мёртвый контрол: serde-рассинхрон BrowserConfig
- Локация: `src-tauri/src/browser.rs` -> 36–56 -> struct BrowserConfig; `src/api.ts` -> 980–986 -> interface BrowserConfig; `src/components/settings/BrowserUseSection.tsx` -> 58–63
- Категория: рассинхрон стыка (тихий отказ + мёртвая поверхность фичи)
- Код:
  ```rust

  // browser.rs:52

  ```
  ```ts

  ```
- Доказательство: Tauri конвертирует snake→camel только для ИМЁН аргументов команды (сам коммит-комментарий api.ts:412–413 это фиксирует); поля вложенной структуры `config` десериализуются чистым serde. Фронт шлёт `{..., allowPrivateNetworks: v}` (BrowserUseSection.tsx:62) → Rust не находит `allow_private_networks` → `#[serde(default = "default_false")]` (browser.rs:51) → **всегда false**. Обратно `browser_get_config` (tooling.rs:515–517) сериализует `allow_private_networks` → фронт читает `cfg.allowPrivateNetworks` → `undefined` → тумблер всегда рисуется выключенным (BrowserUseSection.tsx:61, ToggleRow `on=undefined`→false). Хуже: после первого же getCfg снапшот state содержит snake-ключ `allow_private_networks:false` из ответа сервера, и спред `{...cfg, allowPrivateNetworks: v}` отправляет ОБА ключа — Rust читает snake-ключ со значением false, так что значение не проходит даже в одной сессии.
- Стык: фронт api.ts:992–1011 (browserGet/browserSetConfig) ↔ Rust tooling.rs:515–541 (команды) + browser.rs:36–56 (структура) — механизм склейки serde, тестов на паритет полей нет.

- Последствия: (1) тумблер не применяется никогда — `is_navigable_url(&url, config().allow_private_networks)` (browser.rs:997, 1078) всегда получает false, агент не может ходить на localhost/приватные адреса даже с явного разрешения пользователя; (2) после перезапуска секции тумблер показывает off при любом состоянии; (3) в browser.json всегда пишется `allow_private_networks:false`. Направление отказа fail-safe (запрет остаётся) — дыры безопасности нет, но заявленная фича мертва. Это ровно тот класс бага, который DictationStatus чинил 29.09 (dictation.rs:92–95 — комментарий-урок) и который здесь пропущен во второй структуре.
- Рецепт: `grep -n "rename_all" src-tauri/src/browser.rs` (пусто) и `grep -n "allowPrivateNetworks" src/components/settings/BrowserUseSection.tsx`. Фикс: `#[serde(rename_all = "camelCase")]` на BrowserConfig (или `alias`).

### А3-1. [ВЫСОКИЙ] QuickEntry позиционируется в глобальных координатах без origin монитора и с чужим scale — на мульти-мониторе всплывает не на том экране
- Локация: src-tauri/src/lib.rs -> строки 874–890 -> `position_quickentry`
- Категория: поломка фичи на классе конфигураций (мульти-монитор), рассинхрон стыка «бекенд-геометрия ↔ tao»
- Код (lib.rs:874–890):
```rust
fn position_quickentry(app: &tauri::AppHandle, w: &tauri::WebviewWindow) {
    let monitor = app.cursor_position().ok().and_then(|pos| {
        app.available_monitors().ok().and_then(|ms| {
            ms.into_iter().find(|m| { /* монитор под курсором */ })
        })
    });
    let Some(m) = monitor.or_else(|| w.current_monitor().ok().flatten()) else { return };
    let scale = m.scale_factor();
    let screen_w = m.size().width as f64 / scale;
    let (ww, _wh) = w.inner_size().map(|s| (s.width as f64 / scale, s.height as f64 / scale)).unwrap_or((540.0, 96.0));

}
```
- Доказательство: цель по комментарии (lib.rs:870–873) — «верхний центр монитора под курсором»; находится монитор `m`, но (1) в позицию не добавляется `m.position()` (origin монитора в глобальных координатах), (2) `LogicalPosition` конвертируется tao по scale ОКНА, а не целевого монитора. Расчёт: primary 1920×1080@1.0 в (0,0), второй 2560@1.0 в (1920,0), курсор на втором → screen_w=2560, x=(2560−540)/2=1010 → глобальная точка (1010, 80) лежит в primary → QuickEntry всплывает top-center PRIMARY. - Код:
  ```html
  <!-- index.html:19-21 -->

      background: #1f1e1d;
  ```


- Доказательство (механика + эксперимент на реальном бандле):
  1. По CSS Backgrounds 3 §3.11.2 фон `body` транслируется на canvas **только** если фон корня (`html`) transparent/none.   2. `applyAppearance` снимает только ИНЛАЙН от boot-theme (`appearance.ts:642`); авторское правило фолбэка остаётся. `html.glass body{background:transparent}` спасает только в стекле.
  3. Эксперименты headless-Chromium (Edge, движок семейства WebView2) на **реальном скомпилированном CSS**:
