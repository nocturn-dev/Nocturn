### A7-1. [СРЕДНИЙ] shell_run_timeout_kills_process — платформенно-зависимый тест без cfg-гейта: падает на Linux/macOS
- Локация: src-tauri/src/tools.rs -> 872-877 (тест) и 714-721 (shell-обёртка)
- Категория: тест-зависимость от окружения / CI-стык rust-матрицы
- Код:
```rust
872    fn shell_run_timeout_kills_process() {
873        let res = execute_tool("shell_run", r#"{"command":"Start-Sleep -Seconds 30","timeout_sec":1}"#);
874        assert!(res.is_ok());
875        assert!(res.unwrap().contains("TIMEOUT"));
876    }
```
```rust
718    } else {
719        let mut c = Command::new("sh");
720        c.args(["-c", command]);
721    };
```
- Доказательство: «Start-Sleep» — команда PowerShell; shell_run на unix исполняет через `sh -c` (tools.rs:719) → мгновенный exit 127 «not found», вывод «exit code: 127» без «TIMEOUT» → assert ложно. Соседние тесты гейтят платформу (`if cfg!(windows)` — tools.rs:884-888 тот же файл, hooks.rs:384-387, 413-417, proc.rs:232-238) — класс известен, здесь пропущен.
- Стык: тест-набор ↔ CI rust-матрица (ubuntu-22.04, macos-latest) — cargo test упадёт при следующем push; ветка ahead of origin на 357 коммитов — CI давно не гонялся по актуальному коду. README.md:280 «CI enforces all of them».
- Конфигурация воспроизведения: любой unix; `cargo test shell_run_timeout`.
- Последствия: красная CI-джоба на 2 из 3 ОС; сигнал потерян среди падений.
- Рецепт: `if cfg!(windows) {"Start-Sleep -Seconds 30"} else {"sleep 30"}` — как в proc.rs:232.
