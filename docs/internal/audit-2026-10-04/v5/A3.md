# НАХОДКИ

### 1. [НИЗКИЙ] shellRules DANGEROUS_PATTERNS: фикс 6af9361 неполон — rm с раздельными флагами, PS-алиасы ri/erase, реестр, Format-Volume/Clear-Disk/wsl --unregister проходят мимо сети dangerous
- Локация: src/agent/shellRules.ts -> строки 111–128 (сами паттерны), 130–133 (dangerousShellPattern)
- Категория: рассинхрон стыка (пробой allow-политики подтверждений; продолжение утренней A3-3)
- Код (src/agent/shellRules.ts:115, 123–128):
```ts
  /\brm\s+[^;&|]*-[a-z]*r[a-z]*f/, // rm -rf (цели проверяет юзер вопросом)
...
  /\bremove-item\b[^;&|]*-[a-z]*r/, // Remove-Item -Recurse [-Force]
  /\b(rd|rmdir)\b[^;&|]*\/s\b/, // rd /s /q — деревo каталогов
  /\bformat\b[^;&|]*[a-z]:/, // format c:
  /\bdiskpart\b/,
```
- Доказательство: node-прогон паттернов из файла (это сессия, не по памяти):
  `rm -r -f /tmp/x` → НЕ матч; `rm -fr /tmp/x` → НЕ матч;
  `rm --recursive --force /tmp/x` → НЕ матч (паттерн требует склеенный кластер
  `-…r…f` с одинарным `-`); `ri -recurse ./x` → НЕ матч (алиас Remove-Item);
  `erase -recurse ./x` → НЕ матч; `Remove-ItemProperty -Path HKCU:/Test` → НЕ
  матч (`\bremove-item\b` не пробивает слово-границу внутри
  remove-itemproperty); `reg delete HKLM\... /f`, `reg add ...` → НЕ матч;
  `Format-Volume -DriveLetter C`, `Clear-Disk -Number 1` → НЕ матч (PowerShell
  Storage-командлеты); `wsl --unregister Ubuntu` → НЕ матч. При этом
  `Remove-Item -LiteralPath ./x -Recurse -Force` — матч (утренний кейс закрыт),
  `remove-item -recurse`, `rd /s`, `del /s`, `format c:`, `diskpart`, `dd of=`,
  `mkfs`, `chmod -R 777` — матч (проверено тем же прогоном).
- Стык: src/agent/shellRules.ts:141–148 (classifyShellRun: dangerous → neutral,
  иначе allow при совпадении префикса) → src/agent/toolRules.ts:31
  (`allowRule = !alwaysAsk && classifyShellRun(...) === "allow"`) → useAgentRun
  (auto-allow без подтверждения) + авторитетный сырой префикс-матч бекенда
  (src-tauri/src/perm.rs:197–226). Механика: allow-правило вида
  `shell_run(rm *)`/`shell_run(reg *)` + простая команда с деструктивными
  раздельными флагами → classifyShellRun = "allow" → фронт НЕ спрашивает
  пользователя в Ask/Edit, бекенд пропускает по префиксу.
- Конфигурация воспроизведения: любая ОС (чисто фронтовая логика). Пример:
  permRules.allow = ["shell_run(rm *)"], модель запускает `rm -r -f C:\data`.
- Последствия: обход подтверждения для удаления дерева/записи реестра под
  allow-префиксом. Направление ошибки — «пропустить мимо ask» (не блокировать
  легитимное). Back-end deny работает всегда, Full-режим и так не спрашивает —
  окно экспуатации уже, чем у утренней A3-3, поэтому НИЗКИЙ, а не СРЕДНИЙ.
- Рецепт: `node -e` прогон из доказательства за 30 сек; grep
  `grep -n 'remove-item\|rm\\s' src/agent/shellRules.ts`. Фикс-набросок:
  `/\brm\b[^;&|]*\B-{1,2}[a-z-]*r/` с отдельной проверкой `-f`/`--force`
  (или просто трактовать любой `rm -r*` как dangerous — false positive безвреден,
  уводит в ask), добавить `ri`/`erase` в BARE-набор remove-item, паттерны
  `reg (add|delete|import)`, `remove-itemproperty`, `format-volume`,
  `clear-disk`, `wsl --unregister`.

### 2. [НИЗКИЙ] QuickEntry: комментарий обещает прозрачность на Wayland, код делает непрозрачным весь Linux
- Локация: src/QuickEntry.tsx -> строки 50–58
- Категория: док-дрейф (комментарий противоречит коду); визуальная деградация
- Код:
```tsx
    // На Linux frameless-окно без композитора (X11) вместо прозрачности даёт
    // чёрный прямоугольник — там body красим цветом темы: окно выглядит
    // обычной панелью, а не битым экраном (на Wayland/с композитором
    // прозрачность работает как раньше)
    document.body.style.background =
      getPlatform() === "linux"
        ? `var(--halo-bg, ${STYLE_PALETTES.claude.dark.deep})`
        : "transparent";
```
- Доказательство: условие — `getPlatform() === "linux"` (platform.ts:12–14 —
  UA-токен Linux, на Wayland UA WebKitGTK тот же «X11; Linux»), т.е. ветка
  непрозрачного фона покрывает ВЕСЬ Linux, включая Wayland-сессии с
  композитором, где transparent у окна (tauri.conf.json:33 `"transparent": true`)
  и WebKitGTK прозрачность поддерживают. Комментарий утверждает обратное
  («на Wayland … прозрачность работает как раньше»).
- Конфигурация воспроизведения: Linux, Wayland-сессия (GNOME/KDE), вызвать
  QuickEntry (Ctrl+Alt+Space через портал) — попап выглядит сплошным
  прямоугольником с фоном темы, а не «плавающей» панелью со скруглением и тенью
  (shadow у окна выключен, tauri.conf.json:38 — тень была частью прозрачного
  облика).
- Последствия: пользователь Wayland получает плоский прямоугольник; будущая
  правка «вернуть прозрачность на композиторах» по этому комментарию не будет
  сделана (он утверждает, что уже работает). Функционального отказа нет —
  поэтому НИЗКИЙ.
- Рецепт: `sed -n 50,58p src/QuickEntry.tsx`. Фикс: либо детектировать
  Wayland (в вебвью нельзя напрямую — честно переписать комментарий «весь Linux
  непрозрачен из-за X11-без-композитора»), либо рантайм-флаг с бекенда
  (portal::wayland_session уже есть) через invoke на старте quickentry.

## [ГИПОТЕЗА] (не проверяемо этой сессией, требует рантайма)

- position_quickentry (lib.rs:878–905): на Wayland `app.cursor_position()` и
  `w.current_monitor()` скрытого окна могут не поддерживаться tao-Wayland —
  тогда попап всплывает не «верх-центр монитора под курсором», а в дефолтной
  позиции. Требует ручного прогона на Wayland.
- Unicode NFC/NFD на macOS (приложение Б (г)): NFD-имя файла, пришедшее из
  git-status/core.quotepath=false, может не сматчиться с NFC-путём в
  checkpoint/perm-сравнениях (строковое сравнение без нормализации). Требует
  прогона с реальным NFD-файлом.
- MSRV 1.88 (Cargo.toml:9) vs комментарий «фикс BatBadBut гарантирован MSRV
  1.88» (mcp.rs:306): патч std для cmd-эскейпинга приземлился раньше (1.77.x);
  1.88 скорее всего выбран по другим зависимостям — сверить с rust-toolchain
  при сетевой проверке.
