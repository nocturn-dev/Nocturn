
## 14. Медиа-волна 2: YouTube-плеер + Ambient Lyrics (набросок, 01.10)

### YouTube-плеер внутри Nocturn (следующая волна, решение владельца)
Цель: смотреть YouTube, не покидая Nocturn (без Alt+Tab), с возможностью
свернуть в мини-бар.
- **Плеер**: embed-iframe (youtube-nocookie.com) в отдельной панели/окне —
  по образцу ArtifactsPanel (sandbox без allow-same-origin не подходит:
  YouTube-плееру нужны скрипты + postMessage → отдельный iframe с
  `allow-scripts allow-presentation`, без allow-same-origin).
- **Управление**: YouTube IFrame API (play/pause/seek/переключ видео) —
  кнопки минибара расширяются: у YouTube-источника — прогресс-бар.
- **Сворачиваемость**: панель ↔ мини-бар (полоска с названием + play/pause +
  прогресс), разворот кнопкой. Не Alt+Tab — всё внутри Nocturn.
- **CSP**: `frame-src += https://www.youtube-nocookie.com https://www.youtube.com`
  — единственное расширение периметра; остальные YouTube-домены не нужны.
- **Opt-in**: карточка YouTube в «Интеграциях» (иконка + название, паттерн
  Spotify), по умолчанию выключена.
- **Минусы**: iframe грузит внешние скрипты Google (задокументировать в
  SECURITY.md), autoplay-политики браузера требуют user-gesture, отвлечение —
  поэтому сворачивание обязательно.

### Ambient Lyrics (идея с скрина, 50/50 — набросок)
Лирика как часть ambient-сцены: строки рендерятся в WebGL/GPU-шейдере
(снегопад, неоновый город) и плавают в фикс-зонах; кинетическая
типографика — полупрозрачные зоны с blur, медленный сдвиг, растворение
в частицах при смене фраз.
- **Плюс**: запредельно стильный визуальный ход, ни у кого из конкурентов нет.
- **Минусы**: удар по фокусу (яркие строки дергают боковое зрение во время
  работы), читаемость на процедурном фоне (нужны маски/тени/glow),
  производительность GPU-слоя.
- **Когда**: после YouTube-волны, если медиа-фича зайдет; реализовывать как
  режим сцены AmbientLayer (stars/fog/city → lyrics), а не отдельный слой.

### Telegram-агент (напоминание, крупная волна)
Мониторинг бота + работа агента в ТГ из Nocturn. Архитектуру обсуждать
отдельно: bridge-процесс vs MTProto-клиент, права и безопасность.

#### Требования владельца (02.10, записано с его слов)
1. **Уведомления через бота**: пользователь один раз создаёт бота через
   @BotFather и вставляет токен в Nocturn (токен — в vault). Агент шлёт в
   личку владельцу:
   - **начало работы** (задача запущена: название задачи, модель);
   - **конец работы** (завершена/остановлена/ошибка — как тосты
     финализации сейчас);
   - **триггеры, которые задал пользователь** — настраиваемые события,
     например: ожидание подтверждения (ask_user/confirm), срабатывание
     Hard Limit, ошибка прогона. Минимум — три встроенных тумблера в
     настройках + свободные пользовательские триггеры.
2. **Управление чатом из TG с телефона** (если возможно; владелец точно
   не знает, механику проверить в первую очередь): удалённые команды
   агенту из Telegram-переписки с ботом — отправить задачу/поправку,
   ответить на ask_user, Stop. Вопросы к проработке: bot long-polling
   (без webhook — не нужен публичный URL) vs bridge-процесс, чей токен
   и чей chat_id (привязка «бот → владелец» по первому /start),
   безопасность (токен в vault, команды только от verifed chat_id),
   связь с однопрогонным движком (очередь, activeRunRef-гейты).

## 15. Специнструмент: media_probe
`cd src-tauri && cargo run --example media_probe [-- --toggle]` — диагностика
медиа на живой машине: SMTC-сессии (источник/трек/статус), процессы и заголовки
окон spotify.exe, тест WM_APPCOMMAND-управления. Использовать при любых
проблемах минибара ДО изменения кода.

## 16. Библиотека джейлбрейков для моделей (идея владельца, 02.10 — обсудить и решить в новой сессии)
**Идея владельца**: библиотека готовых jailbreak-промптов для моделей
(например, парсер сайтов, где они лежат) — вставил/выбрал и используешь.

Предварительная оценка (агент, на обсуждение):
- **Стоит делать как ЛОКАЛЬНУЮ библиотеку** (по духу local-first): ручное
  добавление/импорт текстом, хранение в конфиге, подстановка в system
  промт по кнопке рядом с ролями/промпт-библиотекой (инфраструктура
  PromptsSection уже есть — это S/M).
- **Парсер публичных сайтов — спорная половина**: качество/актуальность
  джейлбрейков на сайтах нестабильны, у сайтов ToS против скрейпинга,
  а готовые промпты с чужих сайтов — вектор prompt-injection (вставлять
  ТОЛЬКО как обычный текст, который пользователь прочитал руками).
  Если делать — то как опциональный импортёр с ручным запуском по URL,
  без автоматических обновлений.
- **Риски**: нарушение ToS провайдеров (многие блокируют за jailbreak),
  баны аккаунтов — на стороне пользователя; Nocturn ничего не отправляет
  сам, только текст пользователя его провайдеру (в духе BYOK).
- **Формат решения для владельца**: (а) только ручная библиотека;
  (б) библиотека + ручной импортёр по URL; (в) не делать.
